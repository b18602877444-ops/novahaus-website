# NOVAHAUS 官网产品设计方案

> 版本：v0.1 产品设计稿  
> 当前阶段：信息架构、用户体验与视觉方向  
> 明确边界：本阶段不编写 HTML、React 或 CSS，不进入网站开发。

## 0. 产品定义

### 品牌

**NOVAHAUS**  
**AI Brand & Digital Studio**

### 核心定位

NOVAHAUS 帮助小企业老板、个人 IP、讲师、顾问、创业者和自媒体，把模糊的想法转化为清晰的品牌、可信的内容和高转化的数字体验。

### 官网的核心任务

官网不是服务清单，而是一场经过设计的信任建立过程。它需要在较短时间内回答用户的四个问题：

1. NOVAHAUS 是谁，是否理解我的业务？
2. 你能为我解决什么问题？
3. 你做过什么，结果如何？
4. 我现在应该如何开始？

### 产品目标

- 建立“懂品牌、懂 AI、懂商业结果”的第一印象。
- 用案例和方法论证明能力，而不是只描述服务。
- 让不同类型的客户快速找到适合自己的入口。
- 将高意向访客转化为合格项目线索。
- 让用户在手机端也能完成了解、信任和发起咨询。

### 核心用户

| 用户 | 典型需求 | 最大顾虑 | 需要看到的证明 |
| --- | --- | --- | --- |
| 小企业老板 | 品牌升级、官网、获客 | 不确定投入是否值得 | 清晰方案、真实案例、结果 |
| 个人 IP | 定位、个人品牌、内容系统 | 无法表达自己的价值 | 个人品牌案例、内容方法 |
| 讲师 | 课程品牌、招生页、内容转化 | 页面不能带来报名 | 转化路径、课程案例、流程 |
| 顾问 | 专业形象、线索获取 | 网站看起来不够可信 | 专业表达、客户评价、CTA |
| 创业者 | 从 0 到 1 的品牌与产品叙事 | 时间有限、方向不清 | 快速启动流程、套餐边界 |
| 自媒体 | 内容资产化、商业化 | 流量无法沉淀 | 内容系统、社群或产品路径 |

### 设计原则

1. **Clarity over decoration**：先让用户理解，再让用户惊喜。
2. **Proof before promise**：先展示证据，再表达愿景。
3. **One screen, one decision**：每一屏只推动一个主要认知或动作。
4. **Human strategy, AI leverage**：AI 是效率和洞察的杠杆，人的判断与审美是核心。
5. **Progressive disclosure**：首页保持轻盈，深度信息放到案例、服务和文章页面。
6. **Designed for action**：每个阶段都提供明确、低摩擦的下一步。

## 1. 官网信息架构（Site Map）

### 1.1 顶部导航

建议采用 5 项主导航，保持高级感和认知负担低：

```text
NOVAHAUS
├── Work
├── Services
├── Process
├── About
├── Insights
└── Start a Project  ← 主 CTA
```

### 1.2 页面结构

```text
Home /
│
├── Work /                         案例总览
│   └── Work Detail /              单个案例详情模板
│
├── Services /                     服务总览
│   ├── Brand Strategy & Identity /
│   ├── AI Content Systems /
│   ├── Website & Digital Experience /
│   └── Launch & Growth /
│
├── Process /                      合作流程
├── About /                        品牌与团队
├── Insights /                     文章、方法论、资源
│
├── Start a Project /              项目咨询表单
│   └── Thank You /                提交完成与下一步
│
└── Legal /
    ├── Privacy Policy /
    └── Terms /
```

### 1.3 页面优先级

| 优先级 | 页面 | 作用 |
| --- | --- | --- |
| P0 | Home | 完成定位、建立信任、引导咨询 |
| P0 | Work | 用案例证明能力与结果 |
| P0 | Services | 解释服务范围和适合对象 |
| P0 | Start a Project | 获取项目背景与合格线索 |
| P1 | Process | 降低合作不确定性 |
| P1 | About | 建立品牌人格与价值观 |
| P1 | Work Detail | 展示思考过程和交付深度 |
| P2 | Insights | 形成长期搜索和专业影响力 |
| P2 | Legal | 建立基础合规与信任 |

### 1.4 导航原则

- 桌面端固定显示主 CTA：`Start a Project`。
- `Work` 放在 `Services` 之前，让用户先看证据再看能力。
- 不在主导航中放置过多下拉菜单；服务详情可在 Services 页面内展开。
- 每个页面的导航都保留返回 Work、Services 和 Start a Project 的路径。
- 移动端将导航收纳，但把主 CTA 固定在底部或菜单顶部。

## 3. 每一个版块的作用与内容

### 3.1 Header / 顶部导航

**作用**：建立品牌识别，提供全站方向，并让高意向用户随时发起项目咨询。

**应该出现的内容**：

- NOVAHAUS Logo / Wordmark。
- Work、Services、Process、About、Insights。
- 主 CTA：`Start a Project`。
- 桌面端显示语言切换（如需要）：`EN / 中文`。
- 移动端菜单中优先显示 CTA 和 Work。

**交互原则**：导航项数量少而明确；滚动后保持轻量固定，不遮挡正文。

### 3.2 Hero / 首屏定位

**作用**：让访客立即理解品牌价值，并决定继续浏览还是发起咨询。

**应该出现的内容**：

- 品牌类别：AI Brand & Digital Studio。
- 面向人群：founders、experts、creators、small businesses。
- 结果导向主标题，而不是“我们提供什么服务”的自我介绍。
- 1 个主 CTA + 1 个次 CTA。
- 可识别 NOVAHAUS 的主视觉系统。

**内容要求**：主标题不超过两行；辅助说明不超过 2–3 行；避免堆砌 AI、创新、赋能等抽象词。

### 3.3 Trust Strip / 信任条

**作用**：快速降低陌生品牌的风险感，让用户知道 NOVAHAUS 有真实经验。

**应该出现的内容**：

- 客户 Logo 或客户类型标签。
- 代表性数据：项目数量、服务市场、转化提升等，仅使用真实数据。
- 3 个品牌能力关键词：`Brand clarity`、`AI leverage`、`Digital experience`。

**交互原则**：不要做成夸张的数字墙；每个数据都应该可以被案例或说明支持。

### 3.4 The Real Problem / 问题共鸣

**作用**：让目标客户在网站中看见自己的现状，建立“你理解我”的感觉。

**建议的 3 个问题卡片**：

1. 你的业务有价值，但客户看不懂你是谁。
2. 你的内容很多，但没有形成可持续的品牌系统。
3. 你需要一个网站，但不知道什么才真正推动业务。

**结尾内容**：一句转折文案，说明 NOVAHAUS 将混乱的想法整理为可识别、可传播、可转化的系统。

### 3.5 What We Do / 服务能力

**作用**：把抽象能力转译成用户容易理解的服务入口。

**建议的 4 个服务模块**：

| 服务 | 用户获得的结果 | 适合对象 |
| --- | --- | --- |
| Brand Strategy & Identity | 清晰定位、差异化表达、视觉识别 | 小企业、创业者、个人 IP |
| AI Content Systems | 内容框架、提示词库、生产工作流 | 讲师、顾问、自媒体 |
| Website & Digital Experience | 信息架构、官网、落地页、转化路径 | 所有需要数字门面的客户 |
| Launch & Growth | 上线计划、内容发布、优化与迭代 | 新品牌、新产品、课程项目 |

每张卡片包含：服务名、1 句结果描述、3 个交付关键词、`Explore Service`。

### 3.6 Selected Work / 精选案例

**作用**：以真实工作证明策略、审美和执行能力，是首页最重要的信任模块之一。

**每个案例卡片应该出现**：

- 项目视觉或产品画面。
- 客户类型 / 行业。
- 项目挑战。
- NOVAHAUS 解决方案标签。
- 结果或可验证的变化。
- `View Case Study`。

**展示顺序**：1 个主案例 + 2 个辅助案例。主案例应覆盖核心目标客户，而不是只展示视觉最漂亮的项目。

### 3.7 How We Work / 合作流程

**作用**：降低用户对预算、时间、沟通和交付方式的未知感。

**建议四步**：

1. **Discover**：理解业务、客户与真实问题。
2. **Define**：明确定位、信息架构与成功标准。
3. **Design**：建立品牌、内容和数字体验。
4. **Deploy**：上线、交接、测量与持续优化。

每一步出现：一句解释、主要产出、客户需要参与的内容和预计阶段。不要写模糊的“全案服务”。

### 3.8 Find Your Next Move / 客户自选入口

**作用**：让不同类型客户快速进入相关内容，减少所有人都走同一条路径的认知成本。

**建议入口**：

- `I run a business`：企业品牌、官网与获客。
- `I build a personal brand`：定位、个人品牌与内容系统。
- `I sell knowledge`：课程、讲师品牌与招生转化。
- `I am launching something new`：从 0 到 1 的品牌和数字发布。

每个入口可以跳到服务组合或对应案例，不必新增大量页面。

### 3.9 Human Strategy × AI Leverage / AI 能力说明

**作用**：解释 NOVAHAUS 如何使用 AI，并建立区别于“只会生成内容”的专业认知。

**应该出现的内容**：

- AI 用于研究、整理、原型、内容系统和效率提升。
- 人负责战略判断、品牌取舍、审美、语气、风险和最终质量。
- 一张简单的工作流图：`Insight → System → Expression → Iteration`。
- 一句边界说明：AI 加速过程，但不替代品牌判断。

### 3.10 Proof / 客户评价与结果

**作用**：给已经感兴趣的用户最后一层证据，支持其从“了解”进入“考虑”。

**应该出现的内容**：

- 1–3 条具体客户评价。
- 客户姓名、职位、品牌（获得授权后）。
- 具体变化或结果，而非泛泛的“非常满意”。
- 可用的前后对比：定位、内容效率、询盘、转化、上线速度等。

### 3.11 Insights / 内容与方法论

**作用**：展示思考深度，承接 SEO 流量，并为暂时未准备咨询的用户提供持续接触点。

**内容类型**：

- 品牌定位与表达。
- AI 内容工作流。
- 网站信息架构与转化。
- 小企业和个人 IP 的数字增长。

首页只显示 3 篇最新或最有代表性的内容，每篇显示分类、标题、阅读时间和 `Read Article`。

### 3.12 Final CTA / 最终行动区

**作用**：在用户完成理解和信任后，提供明确的低压力下一步。

**建议内容**：

- 标题：`Your next chapter deserves a clearer system.`
- 辅助说明：说明适合什么项目、提交后会发生什么。
- 主 CTA：`Start a Project`。
- 安心提示：`Tell us where you are. We’ll help you see the next move.`

### 3.13 Footer / 页脚

**作用**：提供完整的收尾导航、品牌记忆和正式信息。

**应该出现的内容**：

- NOVAHAUS 品牌定位。
- Work、Services、Process、About、Insights。
- 邮箱、WhatsApp、社交媒体。
- 地区和工作方式（如远程 / 国际化）。
- Privacy Policy、Terms。
- 简洁的二次 CTA。

## 4. 用户浏览顺序

### 4.1 第一次访问：高意向用户

```text
首屏定位
  ↓
精选案例 / 信任条
  ↓
服务能力
  ↓
合作流程
  ↓
项目咨询表单
```

用户心智变化：

```text
“你是谁？”
  → “你做过什么？”
  → “你能解决我的问题吗？”
  → “合作会怎么进行？”
  → “我可以开始了吗？”
```

### 4.2 第一次访问：低意向或探索型用户

```text
首屏
  ↓
问题共鸣
  ↓
服务 / 客户类型入口
  ↓
Insights
  ↓
订阅或再次访问
```

### 4.3 案例驱动用户

```text
首页 / 搜索
  ↓
Work
  ↓
Case Study
  ↓
相关服务
  ↓
Start a Project
```

### 4.4 访问顺序设计原则

- 第一屏解决“定位”问题，不在首屏直接展示过多服务细节。
- 第二屏尽快提供证据，避免用户只看到自我宣传。
- 中段解释方法和服务，让用户理解合作价值。
- 页面底部承接高意向用户，页面中部提供辅助 CTA。
- 任何页面都不让用户必须返回首页才能开始咨询。

## 5. 用户点击流程

### 5.1 主流程：从首页到项目咨询

```text
Home
  → 点击 Start a Project
  → 项目类型选择
  → 简要项目背景
  → 当前阶段与目标
  → 预算 / 时间范围
  → 联系方式
  → 提交
  → Thank You 页面
  → 下一步说明 / 预约链接
```

### 5.2 案例流程：从证据到转化

```text
Home
  → View Selected Work
  → 筛选客户类型或行业
  → 查看 Case Study
  → 阅读 Challenge / Approach / Outcome
  → 点击相关服务
  → Start a Project
```

### 5.3 客户类型流程

```text
Find Your Next Move
  → 选择“个人品牌 / 课程 / 小企业 / 新项目”
  → 看到对应服务组合与案例
  → 查看合作流程
  → 预约或提交项目简报
```

### 5.4 低摩擦联系流程

```text
任何页面
  → 点击 WhatsApp / Email
  → 自动带入来源页面或项目类型
  → 用户直接发起初步沟通
```

### 5.5 表单体验建议

- 使用分步表单，不要在第一屏展示长表格。
- 第一步只询问：你是谁、需要什么、项目处于什么阶段。
- 预算和时间采用范围选择，降低填写压力。
- 提交前明确说明：预计回复时间、资料用途和隐私处理。
- 提交后给出有价值的下一步，而不是只显示“谢谢”。

## 6. CTA（行动按钮）设计

### 6.1 CTA 层级

| 层级 | CTA 文案 | 目的 | 使用位置 |
| --- | --- | --- | --- |
| Primary | `Start a Project` | 发起正式项目咨询 | Header、Hero、Final CTA |
| Secondary | `View Selected Work` | 查看案例、建立信任 | Hero、案例模块 |
| Secondary | `Explore Services` | 了解服务范围 | Hero 或服务模块 |
| Contextual | `View Case Study` | 深入单个案例 | 案例卡片 |
| Contextual | `See How We Work` | 了解流程 | 流程模块 |
| Low-friction | `Book a Discovery Call` | 高意向用户预约 | 联系页、Thank You |
| Direct | `Chat on WhatsApp` | 即时沟通 | 移动端、页脚、联系页 |

### 6.2 CTA 规则

- 同一视口只设置一个 Primary CTA。
- 主 CTA 始终使用同一语义，不在不同页面反复改名。
- 避免 `Learn More`、`Click Here` 等无法表达结果的弱文案。
- CTA 周围加入降低风险的辅助文案，例如：`No commitment · Tell us what you’re building`。
- 案例页 CTA 应与当前案例相关，例如：`Build Something Similar`。
- 触控设备上的按钮要有足够的点击面积和清晰的状态反馈。

### 6.3 CTA 文案语气

- 清晰：`Start a Project`，而不是 `Let’s Transform Your Future`。
- 有行动感：`View the Work`、`Book a Discovery Call`。
- 不制造压力：避免 `Buy Now`、`Limited Spots` 等不适合品牌咨询的表达。
- 与客户阶段匹配：探索型用户先看 Work，决策型用户直接 Start a Project。

## 7. 手机端布局建议

### 7.1 移动端整体策略

移动端不是桌面端的缩小版，而是“快速判断 + 快速联系”的优先体验。

- 所有内容单列排列，避免两列信息挤压。
- 首屏在不滚动或少量滚动内展示定位、主 CTA 和视觉焦点。
- 使用内容折叠控制服务细节、FAQ 和流程说明的长度。
- 图片优先展示最能代表项目的画面，次要图像延迟出现。
- 关键联系方式始终容易触达。

### 7.2 手机端建议顺序

```text
Logo + Menu + Start
  ↓
Hero 标题与 CTA
  ↓
案例或信任证明
  ↓
问题共鸣
  ↓
服务卡片（单列）
  ↓
精选案例
  ↓
流程
  ↓
客户类型入口
  ↓
评价 / 结果
  ↓
最终 CTA
  ↓
Footer
```

### 7.3 手机端关键交互

- 顶部导航：点击菜单后显示全屏或大面积抽屉式导航。
- 底部操作栏：可固定 `Start a Project` 与 `WhatsApp`，但不同时抢夺注意力。
- 案例卡片：整卡可点击，避免只让用户点击小文字。
- 服务模块：用短摘要 + 展开详情，不默认展示长段落。
- 图片与视频：优先静音、短时、可暂停；不让自动播放阻塞阅读。
- 表单：每一步只展示少量问题，键盘类型与输入格式适配手机。

### 7.4 手机端阅读要求

- 主标题短、强、可扫描。
- 每段正文控制在 2–4 行左右的视觉长度。
- 重要数据与结果使用大数字或短句，不埋在长文中。
- 文字、按钮、链接和表单状态必须有明显对比。
- 所有横向滑动模块都提供可见的下一项提示，避免用户不知道还有内容。

## 8. 配色建议

### 8.1 推荐方向：Obsidian × Paper × Signal

NOVAHAUS 的视觉应该同时表达“高端工作室的判断力”和“AI 产品的未来感”。建议使用深色主场、温暖浅色内容区和一个克制的高亮色。

| 角色 | 颜色 | HEX | 建议用途 |
| --- | --- | --- | --- |
| Obsidian | 深黑 | `#0A0B0D` | Header、Hero、Footer、重点叙事 |
| Paper | 暖白 | `#F5F3EE` | 主内容背景、案例与文章 |
| Ink | 深墨 | `#16181D` | 浅色背景上的正文 |
| Smoke | 灰米 | `#A6A39B` | 次级信息、标签、辅助说明 |
| Signal Violet | 信号紫 | `#7563F5` | AI、链接、交互强调 |
| Volt Lime | 电光黄绿 | `#D9F36A` | Primary CTA、重点状态、少量视觉锚点 |
| Mist | 浅灰米 | `#E6E2D9` | 边框、分割线、卡片层级 |

### 8.2 使用规则

- 70% 使用 Obsidian / Paper 中性底色，保持高级与耐看。
- 20% 使用 Ink / Smoke / Mist，建立信息层级。
- 10% 以内使用 Signal Violet 和 Volt Lime，保持品牌记忆点。
- `Volt Lime` 上使用深色文字，不使用白色小字，以保证可读性。
- Signal Violet 适合表达 AI、链接和交互；Volt Lime 适合表达“开始行动”。
- 不使用大面积彩虹渐变；如需要渐变，只在 Hero 视觉或案例画面中局部使用。

### 8.3 页面色彩节奏

```text
深色 Hero
  → 浅色 Proof / Problem
  → 中性或深色 Services
  → 浅色 Work
  → 深色 AI / Philosophy
  → 浅色 Insights
  → 高对比 Final CTA
```

这种节奏能够让长页面产生呼吸感，也让用户自然感受到品牌的“数字感 + 人文感”。

## 9. 字体建议

### 9.1 推荐字体系统

| 角色 | 拉丁字母 | 中文 | 用途 |
| --- | --- | --- | --- |
| Display | Space Grotesk | 思源黑体 / Noto Sans SC | Hero、页面标题、数字 |
| Body / UI | Inter | 思源黑体 / Noto Sans SC | 正文、导航、表单、按钮 |
| Meta / Label | DM Mono | 思源等宽或系统等宽字体 | 编号、分类、技术感标签 |

### 9.2 字体性格

- **Space Grotesk**：几何、现代、具有工作室和科技感，适合表达 NOVAHAUS 的独特性。
- **Inter**：阅读性能稳定，适合按钮、表单、数据和长正文。
- **Noto Sans SC / 思源黑体**：中文结构清晰，可作为中文主字体。
- **DM Mono**：只用于少量元信息，不用于正文，避免页面变得过度技术化。

### 9.3 排版层级建议

| 层级 | 内容 | 建议 |
| --- | --- | --- |
| Display | 首页主标题 | 大、短、有节奏；控制在 1–2 个核心句 |
| H1 | 页面主标题 | 每页一个，直接表达页面目的 |
| H2 | 模块标题 | 让用户快速理解区块价值 |
| H3 | 卡片 / 小标题 | 说明具体服务或内容 |
| Body | 解释性正文 | 短段落、可扫描、有足够行距 |
| Label | 分类、编号、标签 | 使用大写英文或中英组合，建立系统感 |

### 9.4 中英文字体原则

- 品牌名、服务名、页面标签可以使用英文，强化国际化和工作室气质。
- 解释复杂服务、案例结果和表单问题时优先使用用户熟悉的中文。
- 不为了“高级感”而全站英文；理解效率优先于装饰性。
- 中文和英文混排时保持字号、行高和字重的视觉平衡。

## 10. 关键页面补充规格

### 10.1 Work 页面

- 首屏：`Work that makes the difference visible.`
- 筛选项：客户类型、服务类型、行业、项目阶段。
- 卡片结构：视觉、客户类型、挑战、解决方案、结果。
- 详情页顺序：Context → Challenge → Thinking → System → Outcome → Next Step。

### 10.2 Services 页面

- 首屏先解释“解决什么问题”，再列服务名。
- 每项服务都说明适合对象、典型交付物、合作周期和下一步。
- 使用服务组合而不是孤立的价格表；最终价格需要根据项目范围沟通。

### 10.3 Process 页面

- 展示合作的关键节点、双方责任和反馈方式。
- 说明从首次沟通到启动项目需要哪些资料。
- 公开“如何判断项目适合 NOVAHAUS”，建立专业边界。

### 10.4 Start a Project 页面

建议表单字段：

1. 你的名字与品牌名称。
2. 你属于哪一类客户。
3. 目前最需要解决什么问题。
4. 需要的服务类型。
5. 项目目前处于什么阶段。
6. 预计预算区间。
7. 希望完成的时间。
8. 联系方式与偏好沟通方式。
9. 项目补充说明。

提交完成后应显示：预计回复时间、下一步流程、相关案例或文章推荐。

## 11. 产品成功标准

### 用户层面

- 新访客能够在 5 秒内说出 NOVAHAUS 是什么。
- 目标用户能在 2 次点击内找到与自己相关的服务或案例。
- 用户能够在手机端顺利完成咨询，不需要放大或横向滚动。
- 用户在提交表单前能够理解合作流程、预期和下一步。

### 业务层面

- 主要 CTA 被清晰看见且语义统一。
- 线索表单收集到足够的项目背景，减少无效往返。
- Work 页面成为主要信任资产，而非单纯图片画廊。
- Insights 能持续承接品牌、AI、官网和个人 IP 相关搜索。

### 设计层面

- 视觉系统具备高识别度，但不牺牲内容可读性。
- 每个区块有清晰目的、内容和下一步动作。
- 深色、浅色与高亮色形成稳定节奏。
- AI 的表达体现方法和能力，而不是依赖陈词滥调的科技视觉。

## 12. 本阶段结论

NOVAHAUS 官网应被设计成一个“品牌判断力的体验样本”：它本身就要体现清晰定位、强叙事、系统思考和高质量数字体验。

建议下一阶段依次推进：

1. 确认品牌语气、核心英文标语和首批案例素材。
2. 确认首页内容优先级与最终导航命名。
3. 为首页和 Start a Project 页面绘制更细的低保真线框。
4. 制作视觉方向板（Moodboard）与字体、配色探索。
5. 完成首个案例详情页内容，再进入 UI 视觉设计。

本阶段不进入 HTML、React 或 CSS 开发。
